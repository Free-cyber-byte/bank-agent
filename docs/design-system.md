# ZeroStep 设计规范（v0.7.0 · Win11 Fluent · 含数据专区）

> 目标：像一家银行的正式产品与精算工作台，而不是「AI 套壳聊天页」；同时让视觉本身可复核、可验收。
> 依据：前端方案_Win11_Fluent.md 第 15 节（最终取值）+ 已冻结的前端文件（frontend/index.html 477 行 / 24,606 B、styles.css 974 行 / 57,760 B、app.js 2,434 行 / 112,932 B、_selftest.js 1,043 行 / 67,175 B，2026-10-27；node frontend/_selftest.js PASS=182 FAIL=0）；_preview/win11_v4.html 只作视觉参照，实现以三文件为准；品牌固定 A。
> 本文件是 v0.3.2 的前端验收依据（视觉语言延续 v4，v0.3.2 增补移动端与 PWA）；所有取值均可回指 index.html / styles.css / app.js / manifest.webmanifest / sw.js 的实际实现。

## 一、要避开的「AI 味」

| 反模式 | 为什么像 AI 套壳 | v4 的做法 |
| --- | --- | --- |
| 深蓝紫底 + 青/金渐变 + 发光 | 2023 年以来 AI 产品模板的默认皮肤 | 中性灰底 #F3F5F8 + 单一蓝强调 #0B5FD0（占屏 ≤5%）；全站仅账户卡与品牌标两处渐变，glow 为 0 |
| 大圆角 + 玻璃拟态 + 光晕阴影 | 装饰先于信息 | 圆角 6 / 9 / 14 / 16px 四档，1px 发丝边框，阴影只用中性色且仅浮层用 level-2 |
| 机器人头像 / 闪烁光标 / sparkle / emoji 图标 | 聊天玩具感 | 无头像、无 emoji；状态用色点 + 文字，图标一律内联 SVG |
| 气泡对话占满全屏 | 聊天框思维 | 对话是一条「业务流水」：意图 → 计划 → 工具 → 结论，工具行可展开 |
| 到处都是彩色 | 颜色失去语义 | 颜色只表示状态（自动 / 待确认 / 高风险 / 失败 / 降级） |
| 10–11px 小字省钱式排版 | 信息密度靠缩小字号，字小到不可读 | 17 档字号压到 7 档基础字阶，最小 12px；小字对比度全部 ≥4.5:1 |
| 大号渐变标题 + 营销腔 | 像落地页 | 页标题 28px/36 行高，一句话 + 数据；空态给 3 个真实示例句 |

### 2.3 间距、圆角、阴影

- 间距：8px 网格，常用 4 / 8 / 12 / 14 / 16 / 18 / 22 / 24 / 32 / 40。
- 圆角：--r-1 6px（按钮、输入内件）、--r-2 9px（分段控件）、--r-3 14px（侧栏块、输入条、审批卡）、--r-4 16px（stage、账户卡）、--r-pill 999px（chip、徽章）。
- 阴影：--shadow-1 = 0 1px 2px rgba(16,24,40,.06)（卡片静态）；--shadow-2 = 0 20px 46px -14px rgba(11,18,32,.26)（浮层：审批弹层、抽屉；深色为 0 24px 56px -16px rgba(0,0,0,.72)）。
- 分隔优先 1px 发丝线而非阴影；阴影只用中性色，不允许彩色投影。

### 2.4 动效

- 曲线：--ease = cubic-bezier(.2,.8,.2,1)；印章专用 --ease-stamp = cubic-bezier(.2,.9,.2,1)。
- 时长：--t-fast 150ms（hover / 焦点）、--t-base 200ms（展开 / 切换）、--t-slow 260ms（印章 / 金额逐位）。
- 三段签名动效，只在这三处出现：
  1. 审批通过盖章：印章 260ms 落下 + settle 120ms，合计 380ms；
  2. 审计哈希逐位：行间隔 32ms、位间隔 24ms、帧 56ms，逐位锁定后显示「链校验通过」；
  3. 金额逐位入场：步长 22ms，总时长不超过 628ms。
- prefers-reduced-motion: reduce 时直接落终态，不等待 628ms；不做常驻动画、不做渐变扫光。

### 4.1 插件页与开关（v0.3.0）

- 布局：内容区顶部 .plugins__summary 一行汇总「共 N 个插件 · 已启用 x · 已停用 y · 降级 z」，右侧图例说明「开关即时生效，由服务端持久化；核心插件锁定不可停用」；下方 #pluginsGrid 两列卡片，卡片 align-items:start，展开详情不拉齐同排高度。
- 卡片结构四层：卡头（类别、名称、状态徽章、版本、右侧展开箭头）→ 描述（两行截断）→ 能力 chip（tools / skills / routes 依次取，最多 4 个）→ 卡脚（锁定原因或依赖列表 + 开关）；展开后追加 .plug__detail 四段网格。
- 状态与交互：.plug.is-off 整卡 opacity .62；.plug.is-busy opacity .8 且开关禁用；开关成功后本地更新卡片并联动重载技能、外部服务、渠道、模型与健康状态；失败回滚原状态，显示错误条或 toast（核心插件提示「核心能力不可停用」）。
- 键盘与无障碍：卡头 role=button tabindex=0，Enter / Space 切换展开并阻止默认滚动；开关为 role=switch aria-checked；详情 role=region aria-label「插件详情」。
- 动效：详情面板 fadein；换一批 chips 160ms 淡出再换页；prefers-reduced-motion 下所有动画时长 1ms、直接落终态；只有一批时抖动一次，不做循环动画。

## 五、状态与文案

- 模式分段三态：规则（确定性）/ 自动（有 Key 用模型，无 Key 回退规则）/ 模型（强制模型）。厂商名不作模式名，放在 hover 提示里。
- 降级：外部服务页对应卡显示「降级」标签与 last_error，页头 InfoBar 提示「N 个外部服务不可用，已降级处理」；顶栏无独立降级徽章（v0.2.0 实现）；业务结论里不出现降级文案，只保证金额与边界不变。
- 插件状态三态：已启用（--ok）、已停用（--text-3）、降级（--warn），均配文字，不只靠颜色；停用卡整卡降透明度但名称、能力与依赖仍可读；不提供批量启停，核心插件开关不可点并给出原因。
- 外部数据来源：汇率结果标注 source（external-fx / builtin），审计记 mcp_call / mcp_fallback；外部结果只作为数据展示与加成风险证据，不拼进提示词。
- 每条 Agent 结论标 source：规则 / 模型 / 模型失败已回退 / 技能命中。
- 审批区必须显示：金额、收款人、收款账户、付款账户、时间、来源（原话或模型抽取 + 原句）、为什么需要确认（规则名 + 数字）、执行后会发生什么、倒计时、单次 nonce 声明。
- 「确认环节不经过模型」必须出现在审批卡底部。
- 空态一句话 + 3 个真实示例句，不写「我是你的智能助手」；禁用词：赋能、一站式、智能小助手、魔法、秒懂。
- 数字格式：千分位、两位小数、tabular；卡号/账号掩码；金额单位元，内部整数分。

## 七、数据专区（v0.7.0：仪表盘 / 分析）

专区是「工作台之外的第二块屏」：工作台回答「帮我办一件事」，专区回答「我的钱现在什么状态、和上期比变了多少、要不要动手」。两块屏共用令牌与组件，但信息密度与交互节奏不同——仪表盘是 presentation dashboard（少交互、强层级、看结论），分析页是 exploration dashboard（筛选、排序、对比、分页、导出）。

### 7.1 信息架构：三层，自上而下收敛

1. **结论条**：一句话说清本月结论（支出 / 收入 / 净流入 / 最紧的预算 / 待还），右上角带「数据截至 hh:mm」。
2. **指标层**：4–6 张 KPI 卡，每张必须同时给出「值 + 单位 + 比较基线 + 口径说明」。
3. **下钻层**：趋势、构成、排名、清单、明细；每块都能顺着点到更细的一层（分析页、明细表、CSV）。

不允许把 KPI 铺成十几张卡，也不允许结论条里塞图表：一屏只回答一个问题。

### 7.2 KPI 卡规范

| 元素 | 规则 |
| --- | --- |
| 标题 | 名词短语，2–5 字（净资产 / 可用资金 / 本月支出 / 信用卡待还） |
| 数值 | 28px 等宽数字、千分位、两位小数、带货币符号；不使用缩写（¥24,432.71，不写 ¥2.4万） |
| 比较基线 | 环比用「↑47%」这种紧凑徽章，颜色只表状态（涨支出用 --warn，跌支出用 --ok，持平用中性灰），文案统一「较上月同期」 |
| 口径说明 | 第二行小字，必须能解释这个数字怎么算：「含理财 ¥30,000.00，已扣信用卡待还」「活期 + 储蓄，可直接动用」「收入 − 支出」 |
| 基线不足 | 基准期样本过小（< ¥100）时不给百分比，显示「—」，禁止出现「↑32764%」 |
| 迷你图 | 14 天 sparkline 仅作趋势提示，不标轴、不带交互；有数据表等价（仪表盘趋势图下的「查看数据表」） |

净资产口径固定为 `可用资金 + 理财持仓 − 信用卡待还`，文案必须与之同向（此前写「不含信用卡待还」而算法相减，属于文案错误，v0.7.0 修）。

### 7.3 图表选型

| 数据形状 | 图形 | 禁止 |
| --- | --- | --- |
| 类别差异（商户 / 品类排名） | 水平条，按金额降序，条与条之间留 8px | 不用饼图、不用 3D、不用雷达图 |
| 时间趋势（近 6 月收支） | 分组柱（支出 / 收入）+ 净额虚线，单 Y 轴 | 不做双 Y 轴、不做面积堆叠比较不同量纲 |
| 占比构成（本月支出构成） | 100% 堆叠条 + 图例（类别 ≤6） | 不用环形图做主线（环形只用于单一总量提示，如「本月累计」） |
| 单指标变化 | sparkline | 不加轴与网格 |

通用规则：

- 长度编码从 0 起；负值（净流出）向下延伸，不与正值同向挤压。
- 缺失值 ≠ 0：缺数据的位置留白并在数据表标注「—」，不画成 0 高度的柱。
- 单位与口径写在图标题里（「近 6 个月 · 万元」「柱为支出与收入，折线为净流入；纵轴自 0 起」）。
- 颜色只做编码，不做装饰：类别色 6 档固定，语义色（超支 / 预警 / 正常）与类别色分离；同一含义全站同色。
- 能直标就不靠图例；图例必须可键盘聚焦，并给出「选中 / 隐藏」状态。

### 7.4 每张图必须带的四件套

1. **标题 + 一句话摘要**（如「收支趋势 · 近 6 个月」+ 口径说明）。
2. **单位与时间范围**。
3. **表格等价**：图下方「查看数据表」，`<details>` 内是带 `scope` 表头的真表格。
4. **可访问名称**：SVG 用 `role="img"` + `aria-label`，图形元素加 `<title>`；柱状图每根柱 `tabindex="0"`，聚焦即可读金额。

### 7.5 状态

| 状态 | 表现 |
| --- | --- |
| 首屏加载 | 骨架屏（卡片轮廓 + 脉冲，reduced-motion 下静态），不显示 0 或假数据 |
| 失败 | 卡片内一行说明 + 「重试」按钮，保留页面其余部分可用；不弹全局错误 |
| 空态 | 一句话解释为什么空（「近 30 天没有异常消费」），给一个可执行动作链接 |
| 部分数据 | 环比为 null 显示「—」；构成合计 < 100% 时图例照常列出已知类别，不编造「其他」 |
| 陈旧 | 页头常驻「更新于 hh:mm · 只读」，60 秒可见轮询 + 手动刷新按钮 |

### 7.6 主题与响应式

- 主题三态：跟随系统 / 浅 / 深，写 `localStorage`，只用既有令牌（`body[data-theme="dark"]`），不新增硬编码颜色；深色下正文对比度 ≥5.3:1。
- 断点：≥1380 六列 KPI；1180–1380 三列；≤1180 两列并让「预算执行 / 支出构成」单列堆叠；≤720 单列、图表按容器宽度重绘（`zoneChartWidth()`，390 下文字不缩水）；≤390 表格隐藏账户列，保住「时间 / 摘要 / 金额」。
- 任何断点都不得出现横向滚动：`.zcard` 必须 `min-width: 0`（grid item 默认 `auto` 会被表格 min-content 撑开）。

### 7.7 无障碍与键盘

- 图表不只靠颜色区分：每根柱/段都有 `<title>`，图例文字即类别名。
- 命令面板 `Ctrl/Cmd + K`、`↑/↓` 选、`Enter` 执行、`Esc` 关闭；焦点在打开时移入输入框、关闭后回到触发元素。
- 所有可点区域 `:focus-visible` 有 2px 轮廓；表头 `<th scope="col">`；可排序列用 `aria-sort`。
- 页面不得依赖 hover 才能获得信息（tooltip 同时可键盘聚焦获得）。

### 7.8 验收（v0.7.0 追加）

1. 1440 / 1280 / 390 三档 `scrollWidth == clientWidth`（无横向滚动），深色主题各有一张截图。
2. 结论条、6 张 KPI、趋势图、预算 6 行、构成 6 段 + 图例、待办行、最近 8 行流水全部渲染。
3. 每张图都能展开数据表；每根柱可键盘聚焦并读出金额。
4. 环比为 null 时显示「—」，不出现四位数以上百分比。
5. 分析页：4 个区间预设 + 3 个粒度可用，起止日期回填并与 URL 一致；排序、分页、导出各有断言覆盖（`frontend/_selftest.js` 306 项）。
6. `prefers-reduced-motion` 下骨架与动效直接落终态。

顶栏容量有限：v0.8.1 把二级入口（技能 / 插件 / 外部服务 / 设置）下沉到左栏「更多」分组，顶栏只留工作台 / 业务 / 账户 / 专区四个主入口；≤1560px 收起模式提示文案，≤1240px 收起中段模式切换（更多菜单里仍有同一组开关），≤1300px 服务状态只留圆点，≤1180px 隐藏会话号。平板与手机（≤1024px）改用底部 tabbar 做主导航。

### 9.5 响应式

| 断点 | 行为 |
| --- | --- |
| ≥1380 | 业务页内容整行铺开，右栏三卡 + 执行轨迹同屏 |
| 1180–1380 | 右栏收窄，KPI 仍 4 列 |
| ≤720 | KPI 2 列、域标签横向滚动、构成行改三列 |
| ≤390 | 单列；图表 x 轴标签改「5 月」短式，纵轴标签左留 50px 不被裁 |

### 9.6 验收

1. 1440 / 1180 / 390 三档无横向滚动（`scrollWidth == clientWidth`）。
2. 七个 tab 都能直达 `#/biz/<tab>`，刷新后停在原 tab。
3. 每个数字都能在对话里问到同一个值（同源 `mock_core`）。
4. 右栏三卡在首页常驻，执行一轮对话时计划卡逐步点亮。
5. 任何动作按钮点击后只出现输入框预填 + toast，不产生资金流水、不追加审计事件。
